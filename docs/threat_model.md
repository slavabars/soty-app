# Модель угроз

**Русский** · [English](threat_model.en.md)

Этот документ описывает, что Soty защищает, от кого и что она намеренно не защищает. Это публичный спутник внутреннего журнала аудита, который остаётся приватным.

## Активы

- содержимое сообщений: текст, голосовые заметки, фото, файлы;
- ключи идентичности: Ed25519 (подпись) и X25519 (шифрование);
- локальная база сообщений и медиа-блобы;
- метаданные: кто с кем общается, когда и сколько.

## Противники

1. **Удалённые пиры в libp2p** — любой может подключиться к устройству и прислать фреймы.
2. **Злонамеренные узлы mesh** — соседи по BLE / Wi-Fi Direct могут вставлять, отбрасывать, повторять и переупорядочивать фреймы.
3. **Атакующие на пути** — могут читать, изменять, отбрасывать и повторять трафик.
4. **Недоверенные релеи** — хранят и пересылают непрозрачные конверты; могут быть любопытными, ошибочными или враждебными.
5. **Нашедший потерянное или украденное устройство** — без блокировки приложения.

## Цели безопасности

- **Конфиденциальность и подлинность end-to-end.** Расшифровать может только получатель; каждый принятый конверт подписан отправителем.
- **Привязка ключей.** Ed25519-идентичность подписывает свой X25519-ключ маршрутизации, поэтому релей не может выдать ключ жертвы за свой.
- **Устойчивость к replay без дублей.** Повторный конверт отбрасывается по id и не показывается дважды.
- **Ограниченное потребление ресурсов.** Каждый фрейм, список, буфер и кэш ограничены до выделения памяти, поэтому враждебный пир не исчерпает память.
- **Изоляция на релее.** Релей отдаёт конверт только подписчику, которому он адресован.

## Non-goals

- **Приватность метаданных от релея.** Релей видит время подключений, IP и размеры конвертов. Плейнтекст и ключи — нет. Если это важно, используйте свой релей или mesh.
- **Защита от скомпрометированного устройства.** Root, враждебная ОС,keylogger или разблокированный экран с ключами приложения ломают любой мессенджер.
- **Анонимность против глобального наблюдателя.** Soty скрывает содержимое, но не сам факт связи двух адресов.
- **Защита от неофициальных сборок.** Официальной является только подписанная сборка; пересобранный APK может содержать что угодно.
- **Устойчивость к traffic analysis.** Паддинг ограничен, но не постоянен по скорости.

## Границы доверия

| Граница | Правило |
| --- | --- |
| Wire → парсер | строгий разбор, лимиты размера, `FormatException` на некорректный ввод |
| Парсер → конверт | сдвиг часов → проверка подписи → проверка id → дедупликация → расшифровка |
| Устройство → релей | только непрозрачные конверты после чистой проверки |
| Релей → клиент | только конверты, адресованные ключу подписчика |
| Приложение → ОС | seeds живут в Android Keystore / iOS Keychain, а не в SQLite |

## Криптографические решения

- Ed25519 для идентичности и подписей конвертов;
- X25519 + HKDF для согласования ключей;
- AES-256-GCM для конфиденциальности и целостности полезной нагрузки;
- SHA-256 для id содержимого и опубликованных контрольных сумм релизов.

Статус реализации, остаточные риски и открытые вопросы ведутся в приватном журнале аудита; этот файл никогда не перечисляет эксплуатируемые детали.
